## ✨ Features

1. **Relational Data Model**: `Author` and `Book` entities with a foreign key relationship (`books.author_id -> authors.id`) and cascade deletion (`ondelete="CASCADE"`).
2. **Full CRUD Operations**: Complete Create, Read, Update, and Delete endpoints for both Authors and Books, including pagination and filtering.
3. **Database-Backed Session Authentication**:
   - Write endpoints (`POST`, `PUT`, `DELETE`) require an active user session token.
   - Read endpoints (`GET`) remain publicly accessible.
   - Session tokens are tracked, verified against expiry, and invalidated on logout.
4. **Pure Alembic Migrations**: All table creation and schema changes are managed via autogenerated Alembic revisions without relying on `Base.metadata.create_all()`.
5. **Docker Compose & Automated Startup Migrations**:
   - Multi-container architecture (`db` PostgreSQL 16 Alpine + `api` FastAPI).
   - Container healthchecks ensure PostgreSQL is ready before the API initializes.
   - `entrypoint.sh` automatically runs `uv run alembic upgrade head` before launching `uvicorn`.
6. **Interactive Documentation**: Tested and verifiable via Swagger UI at `/docs` with one-click Bearer token authorization.
7. **Visual Architecture Diagram**: Exported to [docs/architecture.svg](docs/architecture.svg) and embedded in this documentation.

## 📦 Dependency Management Note

> [!NOTE]
> This project uses **[Astral `uv`](https://docs.astral.sh/uv/)** as its native environment and dependency manager.
> - **Source of Truth**: `pyproject.toml` and `uv.lock` define and lock all runtime and development dependencies. The `Dockerfile` executes `uv sync --frozen --no-install-project` for deterministic container builds.
> - **Compatibility File**: `requirements.txt` is exported directly from `uv.lock` via:
>   ```bash
>   uv export --format requirements-txt --no-hashes -o requirements.txt
>   ```
>   It is provided to satisfy exact project specification requirements and will never drift from the locked dependencies.

## 🚀 Quick Start with Docker Compose

Ensure Docker and Docker Compose are installed on your host machine.

### 1. Launch the Services

```bash
docker compose up --build
```

### 2. Startup Lifecycle Execution

Docker Compose orchestrates container startup as follows:
1. The **`db`** container initializes PostgreSQL 16 Alpine and configures persistent storage via the `postgres_data` volume.
2. The healthcheck runs `pg_isready -U postgres -d bookstore` every 5 seconds until healthy.
3. The **`api`** container starts only once `db` is healthy.
4. The container's `entrypoint.sh` executes:
   - Verifies TCP connectivity to PostgreSQL.
   - Executes `uv run alembic upgrade head` to run all pending database migrations automatically.
   - Launches `uv run uvicorn app.main:app --host 0.0.0.0 --port 8000`.

### 3. Access the Application

- **Swagger UI**: [http://localhost:8000/docs](http://localhost:8000/docs)
- **ReDoc UI**: [http://localhost:8000/redoc](http://localhost:8000/redoc)
- **Health Check**: [http://localhost:8000/health](http://localhost:8000/health)

To stop the containers:
```bash
docker compose down
```

## 💻 Local Development with `uv`

All local commands consistently use `uv` and `uv run`.

### 1. Install Project Dependencies

```bash
uv sync
```

### 2. Set Up Environment Variables

Copy `.env.example` to `.env`:
```bash
cp .env.example .env
```
Ensure `DATABASE_URL` is set to your PostgreSQL database (e.g. `postgresql://postgres:postgres@localhost:5432/bookstore`).

### 3. Run Database Migrations

Apply Alembic migrations to your database:
```bash
uv run alembic upgrade head
```

To create a new migration after modifying models:
```bash
uv run alembic revision --autogenerate -m "Add new field"
```

### 4. Start the Development Server

```bash
uv run uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

## 🧪 Testing via Swagger UI (`/docs`)

Open your browser and navigate to **[http://localhost:8000/docs](http://localhost:8000/docs)**.

### Step-by-Step Testing Walkthrough

#### 1. Register a User (Public)
1. Expand `POST /api/v1/auth/register`.
2. Click **Try it out**.
3. Fill in the JSON payload:
   ```json
   {
     "username": "librarian",
     "email": "librarian@example.com",
     "password": "Password123!"
   }
   ```
4. Click **Execute**. Response will return status `201 Created` with the registered user profile.

#### 2. Log In & Obtain a Session Token (Public)
1. Expand `POST /api/v1/auth/login`.
2. Click **Try it out** and enter credentials:
   ```json
   {
     "username": "librarian",
     "password": "Password123!"
   }
   ```
3. Click **Execute**. Copy the `session_token` from the response:
   ```json
   {
     "session_token": "aBcD1234_xyz...",
     "token_type": "Bearer",
     "expires_at": "2026-09-15T22:00:00Z",
     "user": { ... }
   }
   ```

#### 3. Authorize in Swagger UI
1. Scroll to the top right of `/docs` and click the **Authorize** button (padlock icon).
2. Paste your `session_token` into the `Value` field.
3. Click **Authorize**, then click **Close**. All write requests sent from Swagger UI will now automatically include `Authorization: Bearer <session_token>`.

#### 4. Test Protected Authors CRUD
1. **Create Author** (`POST /api/v1/authors` - Protected):
   ```json
   {
     "name": "Frank Herbert",
     "bio": "American science fiction author best known for Dune.",
     "birth_date": "1920-10-08"
   }
   ```
   Returns `201 Created` with the newly assigned `id` (e.g. `1`).
2. **List Authors** (`GET /api/v1/authors` - Public):
   Click **Execute** without authorization to verify public access.
3. **Get Author Details** (`GET /api/v1/authors/1` - Public):
   Returns author info and a list of their books.

#### 5. Test Protected Books CRUD & Foreign Key Relationship
1. **Create Book** (`POST /api/v1/books` - Protected):
   ```json
   {
     "title": "Dune",
     "description": "Epic science fiction novel set on the desert planet Arrakis.",
     "isbn": "978-0441172719",
     "published_year": 1965,
     "price": 19.99,
     "author_id": 1
   }
   ```
   Returns `201 Created`.
2. **Invalid Foreign Key Verification**:
   Attempt to create a book with `author_id: 9999`. The API will reject the request with `404 Not Found: Author with id 9999 does not exist.`
3. **List Books with Author Filter** (`GET /api/v1/books?author_id=1` - Public):
   Lists books written by author `1`.
4. **Update Book** (`PUT /api/v1/books/{id}` - Protected):
   Update price or description.

#### 6. Test Cascade Deletion
1. Call `DELETE /api/v1/authors/1` (Protected).
2. Returns `200 OK: Author with id 1 and all related books deleted successfully.`
3. Call `GET /api/v1/books/1`. Returns `404 Not Found`, confirming cascade deletion.

#### 7. Test Logout & Session Invalidation
1. Call `POST /api/v1/auth/logout`.
2. Returns `200 OK: Successfully logged out. Session has been invalidated.`
3. Try creating an author again. Returns `401 Unauthorized: Session has been terminated.`

## 🗄️ Database Schema & Migrations

### Tables

1. **`authors`**:
   - `id`: `INTEGER` (Primary Key, Autoincrement)
   - `name`: `VARCHAR(150)` (Not Null)
   - `bio`: `TEXT` (Nullable)
   - `birth_date`: `DATE` (Nullable)
   - `created_at`: `TIMESTAMP WITH TIME ZONE`
   - `updated_at`: `TIMESTAMP WITH TIME ZONE`

2. **`books`**:
   - `id`: `INTEGER` (Primary Key, Autoincrement)
   - `title`: `VARCHAR(255)` (Not Null, Indexed)
   - `description`: `TEXT` (Nullable)
   - `isbn`: `VARCHAR(30)` (Unique, Indexed, Nullable)
   - `published_year`: `INTEGER` (Nullable)
   - `price`: `FLOAT` (Not Null)
   - `author_id`: `INTEGER` (Foreign Key to `authors.id`, `ON DELETE CASCADE`)
   - `created_at`: `TIMESTAMP WITH TIME ZONE`
   - `updated_at`: `TIMESTAMP WITH TIME ZONE`

3. **`users`**:
   - `id`: `INTEGER` (Primary Key, Autoincrement)
   - `username`: `VARCHAR(50)` (Unique, Indexed, Not Null)
   - `email`: `VARCHAR(100)` (Unique, Indexed, Not Null)
   - `hashed_password`: `VARCHAR(255)` (Not Null)
   - `is_active`: `BOOLEAN` (Default `True`)
   - `created_at`: `TIMESTAMP WITH TIME ZONE`

4. **`user_sessions`**:
   - `id`: `INTEGER` (Primary Key, Autoincrement)
   - `session_token`: `VARCHAR(128)` (Unique, Indexed, Not Null)
   - `user_id`: `INTEGER` (Foreign Key to `users.id`, `ON DELETE CASCADE`)
   - `expires_at`: `TIMESTAMP WITH TIME ZONE` (Not Null)
   - `is_active`: `BOOLEAN` (Default `True`)
   - `created_at`: `TIMESTAMP WITH TIME ZONE`

### Migrations

Schema generation and database upgrades are powered strictly by Alembic:
- Revisions are autogenerated against SQLAlchemy models via:
  ```bash
  uv run alembic revision --autogenerate -m "<description>"
  ```
- Revisions are applied on container startup via `entrypoint.sh` using:
  ```bash
  uv run alembic upgrade head
  ```
